# 连续创建与多任务工作台 Goal 任务列表

## 1. 文档目的

本文档用于指导开发 Agent 分阶段解决以下问题：用户完成文生图、图生文、图生图、图片修复或高清放大任务后，工作台仍被上一项任务占用，无法顺畅返回并创建新任务。

执行本文档时必须一次只完成一个 Goal。当前 Goal 未通过测试和验收前，不得开始下一个 Goal。

本文档仅是任务计划。创建本文档不代表对应功能已经实现。

## 2. 建设目标

- 已结束任务不再锁定创作工作台。
- 用户可以保留历史作品，同时快速开始同类型或其他类型的新任务。
- 页面刷新后能够正确恢复未结束任务，并正确释放已结束任务。
- 文生图、图生文、图生图、图片修复和高清放大遵循统一状态规则。
- 重试、重新编辑和创建新任务具有清晰边界，不产生重复提交或重复扣费。
- 后续可以从单活动任务逐步升级为后台多任务创作中心。

## 3. 范围说明

### 3.1 本计划包含

- 前端任务状态和工作台锁定规则。
- 创建新任务入口及表单重置。
- 五类图片能力的独立重置策略。
- 刷新恢复、失败重试和取消后的继续创作。
- 后台多任务、任务中心及完成通知。
- 相关接口、状态机、计费幂等和前端自动化测试。

### 3.2 本计划不包含

- 修改图片模型或 AI Provider。
- 修改现有商品、套餐和积分价格。
- 修改 MinIO 文件保存策略。
- 删除用户历史任务或历史作品。
- 在第一阶段重构整个工作台 UI。

## 4. 核心设计原则

1. MySQL 中的任务和计费记录仍是事实来源，浏览器缓存只用于恢复当前交互。
2. 只有非终态任务可以锁定与其直接关联的操作，终态任务不得永久锁定工作台。
3. `succeeded`、`failed`、`cancelled` 是终态；现有后端其他结算中状态仍按非终态处理。
4. 创建新任务必须生成新的浏览器提交上下文和幂等键。
5. 创建新任务只清理当前草稿和活动任务引用，不删除历史作品。
6. “失败重试”“再次编辑”“创建新任务”是三种不同操作，不得复用同一业务语义。
7. 五种创作能力共享任务生命周期，但各自维护表单默认值和字段清理规则。

## 6. 阶段执行顺序

### P0：连续创建最小闭环

执行 `G01 -> G02 -> G03`，优先解决任务结束后无法继续创作的问题。P0 完成后，用户应当能够在保留历史作品的前提下连续创建任务。

### P1：恢复与异常路径完善

执行 `G04 -> G05 -> G06`，统一五种能力的重置行为，并处理刷新、失败、取消和重试场景。

### P2：多任务体验升级

执行 `G07 -> G08`，把单活动任务工作台升级为后台多任务创作中心。P2 不应阻塞 P0 上线。

### P3：正式验收

执行 `G09`，完成五种能力、队列恢复、计费幂等和多设备交互验收。

## 7. G01 任务状态与工作台锁定规则统一

### 目标

建立统一的前端任务状态判断，确保只有正在创建、排队或处理的任务会限制相关操作，终态任务立即释放工作台。

### 任务

- 盘点后端实际任务状态以及前端状态映射。
- 建立统一的 `isTerminalTaskStatus` 和 `isActiveTaskStatus` 判断入口。
- 移除各功能页面自行判断任务是否结束的重复逻辑。
- 明确积分结算中、结果保存中等状态是否继续视为非终态。
- 终态到达后停止轮询、解除表单锁定并保留结果展示。
- 永久性查询错误应停止轮询并释放错误的活动任务引用。
- 加入必要中文注释，说明终态判断与计费状态的关系。

### 交付物

- 统一任务状态判断模块。
- 五种能力接入统一判断。
- 状态判断单元测试。

### 验收标准

- `succeeded`、`failed`、`cancelled` 不再锁定工作台。
- 排队、执行和计费结算中的任务不会被错误判定为完成。
- 同一状态在五种创作能力中表现一致。
- 刷新前后使用相同的状态判断规则。

## 8. G02 任务完成后的“创建新任务”入口

### 目标

在任务终态结果区域提供清晰的新任务入口，让用户无需刷新页面即可继续创作。

### 任务

- 在成功结果中提供“创建新任务”主操作。
- 在失败和取消结果中提供“创建新任务”操作。
- 保留“下载结果”“查看详情”“再次编辑”“失败重试”等已有操作。
- 明确操作差异：失败重试复用原任务输入，创建新任务建立全新草稿。
- 五种能力使用统一按钮位置、文案和交互反馈。
- 按桌面、平板和移动端调整按钮布局，避免按钮溢出或遮挡结果。
- 按钮点击期间提供防重复点击状态。

### 交付物

- 统一的新任务操作组件或事件入口。
- 成功、失败、取消三类结果页面接入。
- 响应式样式和交互测试。

### 验收标准

- 任意终态任务均可创建新任务。
- 点击入口不会删除上一项任务和历史作品。
- 快速连续点击不会创建多个草稿或重复提交。
- 移动端和桌面端都能完整显示操作按钮。

## 9. G03 活动任务与创作表单安全重置

### 目标

点击“创建新任务”后，正确结束上一项任务的前端交互上下文，并恢复可编辑的新草稿状态。

### 任务

- 停止上一任务的轮询定时器和网络恢复计时器。
- 清除前端 `active_task_id` 和与其绑定的活动任务类型。
- 清除已经确认或失效的待提交恢复记录。
- 为新草稿生成新的提交上下文和幂等键。
- 清除当前结果面板中的“本次结果”，但保留作品历史。
- 清除任务级错误、进度和按钮禁用状态。
- 默认保留当前创作能力，用户可以主动切换其他能力。
- 防止上一任务的延迟响应覆盖新草稿状态。

### 交付物

- 统一的 `startNewDraft` 或等价工作台重置流程。
- 活动任务清理和竞态保护测试。
- 浏览器存储清理规则说明。

### 验收标准

- 新草稿具有新的幂等键。
- 上一任务停止轮询，延迟响应不会污染新任务。
- 历史作品仍可查看、下载和再次编辑。
- 用户无需刷新页面即可提交下一项任务。

## 10. G04 五种创作能力分模式重置

### 目标

为每种创作能力定义明确的字段清理和默认值恢复规则，避免不同任务参数相互污染。

### 任务

- 文生图：清理提示词、负向提示词和本次参数，恢复默认模板与尺寸策略。
- 图生文：清理上传图片和本次分析结果，恢复默认理解模型。
- 图生图：清理参考图、编辑说明、编辑模式和画布标注。
- 图片修复：清理原图、蒙版、修复区域和修复说明。
- 高清放大：清理输入图、放大倍率和本次结果。
- 明确哪些用户偏好可以保留，例如质量档位或最近使用模型。
- 切换创作能力时清理不兼容字段和文件引用。
- 为每种模式增加独立测试，防止后续新增模式破坏已有行为。

### 交付物

- 五种模式的草稿默认值和重置函数。
- 模式切换兼容规则。
- 分模式单元测试。

### 验收标准

- 新任务不会带入上一任务的输入文件或结果文件。
- 不同模式之间不会共享不兼容参数。
- 用户明确允许保留的偏好仍然有效。
- 后续新增创作模式时可以独立注册重置策略。

## 11. G05 页面刷新与活动任务恢复

### 目标

页面刷新或浏览器重新打开后，正确恢复未结束任务；如果任务已经结束，则展示结果并允许立即创建新任务。

### 任务

- 页面加载时读取活动任务 ID，并向后端查询真实任务状态。
- 非终态任务恢复轮询、进度文案和必要的操作限制。
- 终态任务恢复结果、停止轮询并解除工作台锁定。
- 活动任务不存在、无权限或已删除时清理本地引用。
- 临时网络错误保留任务引用并按退避策略恢复查询。
- 防止不同登录用户复用同一浏览器中的旧活动任务引用。
- 明确多标签页同时打开时的同步策略。

### 交付物

- 页面启动恢复流程。
- 本地活动任务数据版本和用户隔离规则。
- 刷新、断网恢复和永久错误测试。

### 验收标准

- 刷新不会丢失正在处理的任务。
- 已完成任务刷新后不会重新锁定工作台。
- 无权限或不存在的任务不会造成无限轮询。
- 切换登录用户后不会看到上一用户的活动任务。

## 12. G06 失败、取消和重试后的继续创作

### 目标

统一异常任务的操作路径，使用户可以选择重试原任务或放弃原任务并创建新任务，同时保证计费幂等。

### 任务

- 失败结果同时提供“重试”和“创建新任务”。
- 取消成功后立即进入终态并释放工作台。
- 重试沿用后端允许的原任务输入与计费边界，不伪装成新任务。
- 创建新任务生成新的幂等键和独立计费边界。
- 明确不可重试错误的中文提示，不显示无效重试按钮。
- 处理积分释放或结算待对账状态，避免提前允许危险操作。
- 覆盖重复点击、响应超时和 Worker 重启场景。

### 交付物

- 失败、取消、重试操作矩阵。
- 前后端错误状态映射。
- 计费幂等与异常恢复测试。

### 验收标准

- 重试不会重复预占或重复扣除积分。
- 创建新任务不会复用旧任务的幂等键。
- 取消或失败后可以继续创作。
- 待对账任务按照计费规则展示，不会被错误当成普通完成任务。

## 13. G07 后台多任务与任务中心

### 目标

将“单活动任务锁定整个工作台”升级为“任务后台执行、用户继续创建”的多任务体验。

### 任务

- 将草稿状态与运行中任务状态完全分离。
- 支持用户提交任务后立即创建下一份草稿。
- 建立任务中心，展示排队中、执行中、已完成和失败任务。
- 每个任务独立轮询或使用统一任务列表刷新机制，避免大量定时器。
- 支持按任务类型、状态和时间筛选。
- 明确并发任务上限、排队提示和限流错误。
- 保证任务列表只展示当前用户有权访问的数据。
- 保持 MySQL 为状态事实来源，Redis/BullMQ 只负责运行队列。

### 交付物

- 独立任务中心。
- 多任务状态管理模块。
- 并发限制和任务列表接口适配。
- 多任务端到端测试。

### 验收标准

- 一个任务执行时可以继续创建其他任务。
- 多个任务的状态和结果不会互相覆盖。
- 并发上限提示清晰，超限不会重复扣费。
- 页面刷新后可以恢复所有未结束任务。

## 14. G08 任务完成通知与结果定位

### 目标

当用户在其他创作页面操作时，仍能及时得知后台任务结果并快速定位作品。

### 任务

- 在全局导航或任务中心增加运行中任务数量。
- 任务成功、失败或取消时显示非阻塞通知。
- 通知可以跳转到对应任务详情或结果作品。
- 对同一状态变化只通知一次。
- 页面重新获得焦点时刷新任务状态。
- 移动端使用不遮挡主要操作的通知布局。
- 通知不得暴露 Provider 原始错误或内部敏感信息。

### 交付物

- 全局任务角标和通知组件。
- 任务结果定位交互。
- 通知去重测试和响应式验证。

### 验收标准

- 用户离开当前创作模式后仍能收到任务完成提示。
- 点击通知可以准确打开对应结果。
- 同一任务不会重复弹出完成通知。
- 通知不会遮挡移动端的主要操作区。

## 15. G09 全链路测试、灰度与验收

### 目标

验证连续创建、多任务、刷新恢复、计费幂等和不同设备交互达到上线要求。

### 任务

- 覆盖文生图、图生文、图生图、图片修复和高清放大的完整流程。
- 覆盖成功、失败、取消、不可重试、网络中断和页面刷新。
- 覆盖连续创建至少三项任务以及跨模式创建。
- 覆盖重复点击、相同幂等键重放和不同幂等键新建。
- 覆盖 Redis 短暂不可用、Worker 重启和队列恢复。
- 验证积分预占、成功结算、失败释放和待对账状态。
- 使用桌面、平板和移动端视口检查布局、按钮和通知。
- 增加灰度开关或回滚说明，避免升级失败后阻塞全部创作能力。
- 更新 README、开发文档和用户可见操作说明。

### 建议验证命令

```bash
npm run build
npm run lint
npm run format:check
npm test
npm run acceptance
```

### 验收标准

- 五种能力均可完成“创建 -> 执行 -> 查看结果 -> 创建新任务”。
- 连续创建和后台多任务不会造成任务结果串用。
- 队列重投、Worker 重启和重复提交不会重复扣费。
- 页面刷新和临时断网后可以恢复正确状态。
- 桌面、平板和移动端不存在按钮溢出、遮挡或不可操作问题。
- 全部自动化测试和人工验收通过后，方可将 G09 标记为已完成。

## 17. Agent 执行约束

- 开始 Goal 前先读取本文档、根目录协作规范和相关现有实现。
- 开始时将对应 Goal 状态改为 `执行中`，验收完成后再改为 `已完成`。
- 不得提前把未实现或未验证的 Goal 标记为已完成。
- 代码中的状态流转、幂等、计费、恢复和竞态处理必须写必要的中文注释。
- 前端改动必须验证桌面、平板和移动端。
- 不得修改或提交真实密钥、`.env`、用户生成文件和运行日志。
- 若当前 Goal 发现后端契约不足，应记录阻塞原因和所需接口，不在前端伪造业务状态。
